# realestatecrawler

에이스하이엔드 성수타워(서울 성동구 성수이로10길 14) 근처의 **신규 월세 매물**을 다방·직방에서 1시간마다 수집해,
이전에 없던 매물만 위치 지도와 함께 메일로 알려 주는 Windows 서비스입니다. C# / .NET 10.

## 조건

| 항목 | 값 | 설정 키 (`appsettings.json` 의 `Crawler`) |
|---|---|---|
| 중심 | 37.540131, 127.05679 (에이스하이엔드 성수타워) | `CenterLat`, `CenterLng` |
| 반경 | 1km (직선거리) | `RadiusKm` |
| 거래 | 월세 (반전세 포함) | — |
| 유형 | 원룸, 투룸, 오피스텔, 아파트 | — |
| 층 | 2층 이상 | `MinFloor` |
| 월세 | 60만원 이하 (관리비 제외) | `MaxMonthlyRent` |
| 주기 | 60분 | `IntervalMinutes` |

수집하는 카테고리는 7개입니다.

- 다방: 원룸·투룸, 오피스텔, 아파트
- 직방: 원룸, 빌라·투룸(쓰리룸 이상 제외), 오피스텔, 아파트

## 신규 판정과 메일

- **처음 수집은 메일을 보내지 않습니다.** 카테고리마다 첫 성공 수집을 기준선으로 저장합니다.
- 두 번째 수집부터는 한 번도 본 적 없는 매물만 모아 메일 한 통으로 보냅니다. 신규가 없으면 메일도 없습니다.
- 한 카테고리가 실패해도 그 회차에서 빠질 뿐입니다. 복구된 뒤 기존 매물이 한꺼번에 "신규"로 쏟아지지 않습니다.
- 메일 발송이 실패하면 그 매물은 본 것으로 기록하지 않고 다음 회차에 다시 보냅니다.
- 다방과 직방에 같은 집이 올라와 있으면 두 건으로 옵니다 (사이트 간 같은 매물을 확실히 가려낼 방법이 없음).

메일 예시 (제목 `[성수] 신규 월세 2건`). 매물마다 세 덩어리입니다.

- **매물 이름**: 사이트에 올라온 매물 제목이고, 누르면 그 매물의 다방/직방 페이지가 열립니다.
  제목이 없으면 "광진구 화양동 원룸"처럼 위치와 유형으로 대신합니다.
- **요약 한 줄**: 사이트, 유형, 월세, 층, 면적, 위치.
- **위치 지도**: 빨간 점이 매물, 파란 점이 에이스하이엔드 성수타워입니다. 지도를 눌러도 매물 페이지가 열립니다.

```
풀옵션 신축 투룸, 성수역 도보 7분                      ← 다방 매물 페이지 링크
[다방] 투룸 · 월세 1000/60 · 3층 · 42.97㎡ · 자양동
[지도 이미지]

광진구 화양동 원룸                                     ← 직방 매물 페이지 링크
[직방] 원룸 · 월세 300/50 · 옥탑방 · 17㎡ · 광진구 화양동
[지도 이미지]
```

직방 아파트는 매물별 고정 주소가 없어 단지 페이지로 연결됩니다.

## 메일 설정

메일은 SMTP 로 보냅니다. 기본값은 네이버 메일(`smtp.naver.com`, 465 SSL)입니다.

1. **SMTP 켜기**: 네이버 메일 > 환경설정 > POP3/IMAP 설정 > IMAP/SMTP 사용을 '사용함'으로 바꿉니다.
2. **비밀번호 파일**: 비밀번호 한 줄만 든 텍스트 파일을 저장소 밖(또는 `.gitignore` 된 곳)에 둡니다.
   2단계 인증을 쓰는 계정은 계정 비밀번호 대신 애플리케이션 비밀번호를 발급받아 넣습니다.
3. `src/RealEstateCrawler/appsettings.Local.example.json` 을 같은 폴더의 `appsettings.Local.json` 으로 복사하고 값을 채웁니다.

```json
{
  "Mail": {
    "To": "your-id@naver.com",
    "From": "your-id@naver.com",
    "SmtpHost": "smtp.naver.com",
    "SmtpPort": 465,
    "UseStartTls": false,
    "UserName": "your-id",
    "PasswordFile": "C:\\path\\to\\smtp-password.txt"
  }
}
```

| 항목 | 설명 |
|---|---|
| `To` | 받는 주소. 비우면 메일 대신 로그에만 남깁니다 |
| `From` | 보내는 주소. 네이버·지메일은 SMTP 계정 자신의 주소여야 합니다. 비우면 `To` 를 씁니다 |
| `SmtpHost` / `SmtpPort` | 네이버 `smtp.naver.com` / `465`, 지메일 `smtp.gmail.com` / `465` |
| `UseStartTls` | `true` 면 STARTTLS(보통 587), `false` 면 접속부터 SSL(보통 465) |
| `UserName` | SMTP 로그인 아이디. 네이버는 주소의 `@` 앞부분, 지메일은 전체 주소 |
| `PasswordFile` | 비밀번호 파일 경로. 보낼 때마다 다시 읽으므로 비밀번호를 바꿔도 재설치가 필요 없습니다 |
| `Password` | 파일 대신 비밀번호를 직접 넣을 때. 설치 폴더(`C:\Program Files`)로 복사되므로 파일 쪽을 권장합니다 |

`appsettings.Local.json` 은 `.gitignore` 에 들어 있어 커밋되지 않습니다. 메일 주소와 비밀번호 경로는 이 파일에만 둡니다.
`To` 는 있는데 비밀번호를 읽지 못하거나 로그인이 실패하면 로그에 `메일 발송 실패` 가 남고, 그 매물은 다음 회차에 다시 보냅니다.

## 실행

```powershell
# 지금 조건에 맞는 매물을 한 번 출력만 (상태 저장·메일 없음)
dotnet run --project src/RealEstateCrawler -- --dry-run

# 설정한 주소로 시험 메일 한 통
dotnet run --project src/RealEstateCrawler -- --test-mail

# 단위 테스트
dotnet test
```

### Windows 서비스로 상시 실행

관리자 PowerShell 에서:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install-service.ps1
```

- `C:\Program Files\RealEstateCrawler` 에 배포하고 `RealEstateCrawler` 서비스를 자동 시작으로 등록합니다.
- 프로세스가 죽으면 1분 뒤 자동으로 다시 띄웁니다.
- 코드나 `appsettings.Local.json` 을 바꾼 뒤 같은 스크립트를 다시 돌리면 갱신됩니다.
- 제거: `scripts\uninstall-service.ps1`

상태와 로그는 `C:\ProgramData\RealEstateCrawler` 에 있습니다.

- `state.json`: 기준선을 잡은 카테고리, 본 매물과 마지막으로 본 시각 (30일 동안 안 보이면 지움)
- `logs\crawler-YYYYMMDD.log`: 회차별 수집 건수, 신규 매물, 오류
- `tiles\`: 지도 타일 캐시 (30일 지나면 다시 받음)

`state.json` 을 지우면 다음 회차가 다시 "첫 수집"이 되어 메일 없이 기준선만 잡습니다.

## 동작 방식

두 사이트 모두 공식 API 가 없어 웹사이트가 쓰는 내부 API 를 그대로 호출합니다. 사이트가 바뀌면 깨질 수 있고,
그때는 로그에 `수집 실패` 가 남습니다.

- **다방**: `api/v5/room-list/category/{one-two|officetel|apt}/bbox`. 웹 클라이언트 헤더(`csrf`, `D-Api-Version` 등)가 필요합니다.
  원룸·투룸은 서버 필터로 2층 이상·옥탑만 받고, 나머지는 받은 뒤 층을 거릅니다.
- **직방 원룸·빌라·오피스텔**: `house/property/v1/items/{onerooms|villas|officetels}` 로 geohash(5자리) 셀마다 매물 번호와 좌표를 받고,
  반경 안 번호만 `items/list`(한 번에 15건)로 상세를 읽습니다. 직방 웹은 geohash 를 AES-256-CBC 로 암호화해 보내므로 같은 방식으로
  암호화합니다. 키는 직방 웹 번들에 들어 있는 값이며, 직방이 키를 바꾸면 `ZigbangGeohashKey` 만 고치면 됩니다.
- **직방 아파트**: `apt/nearby-danjis` 로 반경 안 단지를 찾고 단지마다 `apt/danjis/{id}/item-catalogs`(월세)를 읽습니다.
  링크는 단지 페이지로 연결됩니다.

요청 사이에 0.25초씩 쉬며, 한 회차는 보통 20초 안팎에 끝납니다 (직방 아파트는 반경 안 단지 수만큼 요청).

- **위치 지도**: 다방·직방의 지도는 각 사이트 전용 키로 도는 네이버·카카오 지도라 가져다 쓸 수 없습니다.
  대신 사이트가 주는 매물 좌표로 [OpenStreetMap](https://www.openstreetmap.org/copyright) 타일을 이어 붙여 600×360 JPEG 를 그리고
  메일 본문에 인라인 이미지로 넣습니다. [타일 이용 정책](https://operations.osmfoundation.org/policies/tiles/)에 따라
  앱을 밝히는 User-Agent 를 보내고, 받은 타일은 30일 동안 캐시하며, 지도 오른쪽 아래에 출처를 적습니다.
  매물이 모두 같은 동네라 타일은 거의 캐시에서 나옵니다. 지도를 그리지 못하면 그 매물만 지도 없이 나갑니다.

## 자동 결정 기록

요청에 명시되지 않아 아래처럼 정했습니다. 모두 설정이나 코드 한 곳만 바꾸면 됩니다.

2026-10-27 처음 만들 때:

- **"부근" = 반경 1km**: 도보 15분 남짓. `RadiusKm` 으로 조절.
- **"신규" = 지금까지 본 적 없는 매물**: 직전 회차만 비교하면 지도 경계나 목록 흔들림으로 사라졌다 다시 보이는 매물이 반복해서 알림으로 옵니다.
  그래서 최근 30일 안에 한 번이라도 본 매물은 다시 보내지 않습니다.
- **층 판정**: 숫자 층은 2 이상만, 지하·반지하는 제외, 옥탑은 포함.
  사이트가 정확한 층을 숨기는 "저층/중층/고층"과 층 정보가 없는 매물은 놓치지 않도록 포함하고 알림에 그 표기를 그대로 적습니다.
- **투룸 범위**: 다방 원룸·투룸 카테고리, 직방 원룸·빌라의 투룸(room_type 04)까지. 쓰리룸 이상 빌라는 제외.
  오피스텔·아파트는 방 개수와 관계없이 포함.
- **실행 계정 = LocalSystem**, 상태는 `%ProgramData%`.

2026-10-27 알림을 문자에서 메일로 바꿀 때:

- **SMTP 직접 발송**: 별도 가입이나 요금 없이 쓰던 메일 계정으로 보냅니다. 같은 계정을 쓰는 다른 프로그램과 비밀번호 파일을 공유할 수 있게 `PasswordFile` 로 경로만 가리킵니다.
- **회차당 메일 한 통, 건수 제한 없음**: 문자는 요금 때문에 회차당 5통으로 막았지만 메일은 비용이 없어 신규 매물을 한 통에 모두 담습니다.
- **받는 주소가 있는데 보내지 못하면 다음 회차에 재시도**: 비밀번호 파일이 없거나 로그인이 실패해도 매물을 잃지 않습니다.

2026-10-27 월세 상한·지도·매물 이름 링크를 넣을 때:

- **"월60" = 관리비를 뺀 월세 60만원 이하**: 60만원은 포함합니다. 직방 아파트처럼 가격이 범위로 묶인 매물은 최저 월세로 봅니다.
  월세를 읽지 못한 매물은 놓치지 않도록 남깁니다.
- **상한을 넘던 매물이 값을 내리면 그때 신규로 알립니다**: 상한을 넘는 매물은 본 매물로 기록하지 않기 때문입니다.
- **지도 = OpenStreetMap 타일**: 키·가입이 필요 없고, 네이버·카카오 정적 지도는 별도 가입과 키가 필요합니다.
  기준 건물(파란 점)을 함께 찍어 얼마나 떨어져 있는지 바로 보이게 했습니다.
